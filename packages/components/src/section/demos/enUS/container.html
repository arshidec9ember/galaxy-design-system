Anatomy

The header and footer have configurable limitations, but the body section can accommodate information that is related to the use case at hand.

Elements

The Section container component comes with two configurable parts. Next, we see deep dive into both of the aforementioned component parts

Header

Section Container header acts as a mega identifier to provide extra context.

Footer

The footer has a container area that can hold Button Groups. The purpose of the footer is to provide a set of context-specific actions. It is an optional entity that can be toggled on/off based on the use case.

Behaviors

Height

  • Section Container height is responsive since it depends upon the elements placed in the body.

  • The height of the header and footer is fixed. Whereas that of the body is responsive.

Width

It has a fluid width which is set based on the number of layout columns required for it. And therefore it is responsive based on the width of the columns. The number of columns to span it across is decided based on the context.

Example below:

  • 3 Column Grid - 4x4x4

  • 2 Column Grid - 8x4

  • 2 Column Grid - 6x6

  • 1 Column Grid - 12

Text Overflow

The title and the description auto-truncate with elipses based on the available space. Hovering over the truncated title or the description shows a tooltip with the complete text.

Usage Guidelines

Don’t

  • Avoid using too many elements in the header with a smaller width container

  • Avoid compressing the title, consider using icon buttons, action overflow Dropdown menu or larger width section containers.
