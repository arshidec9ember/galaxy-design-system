Anatomy

A form field is a compilation of many items that guide the user in performing an input action,

  • Field Container: By default, the container has white filled, which helps in creating contrast between the text field and surrounding content.

  • Label: Label text is used to inform users as to what information is requested for a text field.

  • Mandatory asterisk: To indicate that a field is required, display an asterisk (*) next to the label text and mention near the form that asterisks indicate required fields.

  • Input Value: Input value is the user's data entered into a text field.

  • Help Icon: A text field can have a help icon above the field to give extra context or instruction about what a user should input in the field.

  • Optional: Used as an indicator if the field is optional.

  • Error Text: This is used to communicate an error when the field requirements aren’t met, prompting a user to adjust what they had initially input.

  • Character count: To indicate the number of characters the user will be able to input.

  • Icon: Trailing icon is mainly used for actions like erasing the text in the field with a cross icon, showing a password with an eye icon or giving voice input with a microphone icon, etc. It can also be used to notify users about valid inputs (if invalid there will be an error text).

  • Prepend/Append: Form fields contain different parameters that control and facilitate the user inputs.

Variations

In GDS form fields are categorized into 8 Variants; Text field, Text area, Select field, Combobox, Search, Password, File picker, and Date-time picker. Each variant contains its own set of states and properties that are configured based on the usage.

The components are further integrated with features allowing the user to have better usability along with the Default type.

States

Form field interactions aid users in understanding every state of the component the user interacts with, each state represents an action that is either performed or triggered in the course of form filling.

  • Normal state: Normal state is the default state of the component before the user interacts or performs any action over it

  • Hover state: Hover state is a trigger point when the user interacts with the component by hovering over the component using the mouse cursor, here subtle change in color values indicates the action performed, and a state change.

  • Active state: Active state is triggered on the course when the user interacts with the component till he moves to the next field or clicks outside.

  • Filled state: A filled state of the component contains the information the user has inputted in the given field.

  • Focussed state: Focused is triggered when the user uses the keyboard to navigate to the field.

  • Disabled state: Disabled state is an inactive state of the component in which the user will not be able to interact with the component, a state change can be triggered by providing permission to edit or by performing a prerequisite action.

  • Error state: Upon performing validation on the given input the system throws an error aiding the user to enter the correct information.

  • Uploaded state: The uploaded state is equivalent to the filled state with information updated in the file picker component.

Anatomical behavior

Place holder text

Placeholder text provides hints or examples of what to enter. Placeholder text disappears after the user begins entering data into the input and should not contain crucial information.

Required/Optional

Text fields can be marked as optional or required, depending on the data input needed, Required/Optional field is marked with an asterisk next to the form field label

Prepend / Append

Form fields can facilitate other actions other than just entering the input value. To provide a guided journey to the user Prepend/Append allows us to configure components with a set of parameters that can control user input. Positioning and usage of the Prepend/Append can vary depending upon the context of usage.

Help Icon

To give extra context or instruction about what a user should input in the field a Help icon can be used to indicate additional information near the field label, on mouse hover a Tooltip will open along with the message/instructions.

Character count

Character count helps users know how much text they can enter when there is a limit on the number of characters. The character count is used in both the text field and text area, by default the count is set to indefinite and can be specified based on need.

Single line error

Error text tells a user how to fix the error by re-stating the input requirements or describing the necessary interaction. Try to keep the tone of the error message short, clear, and helpful.

Multi-line error

A Multiline error acts similar to a single line error but is triggered when multiple errors are found when the information is entered, a multi-line error can wrap to form another line descriptive up to two lines or it can be listed down as bullet points.

Layout behavior

Text overflow

When the field label is too long for the available horizontal space, it wraps to form another line. The field text itself truncates

Width

The width of a text field can be customized appropriately for its context.

If a form field is used inside containers like modals and side sheets, it is advisable to use the component in full width. In the case of a full-screen layout, a grid has to be used to structure them symmetrically.

Field grouping

Mark the minority of text fields in a form as required or optional. In a single form, mark only the required fields or only the optional fields, depending on whichever is less frequent in the entire form.

All fields are optional unless highlighted as mandatory or All fields are mandatory unless highlighted as optional

Component behavior

Text Field

The text field allows users to input information through the keyboard, the text field input is primarily used for long or short information entries.

Select Field

The select field allows users to choose from a list of options in a limited space. The list of options can change based on the context. Those could be covered under popover component documentation.

Combo Box

Combo boxes combine a text entry with a picker menu, allowing users to filter longer lists to only the selections matching a query. This can either have a single select or multiple selects.

Based on the content, the width of the combo box can vary. If there’s enough width then preferably use full width but in the case of fixed width, the height of the combo box will try to adjust according to the content.

Password field

The Password field, by default, contains hidden text that can only be viewed by using the “eye icon” in place of the icon placeholder provided to facilitate the “Show/Hide Password” feature.

File Picker

The file picker is used for inline single file uploading.

Text area

The text area lets a user input a longer amount of text than a standard text field. It can include all of the standard validation options supported by the text field component.

Text areas can display a character count indicator when the length of the text entry needs to be kept under a predefined value.

Date & Time Picker

Date and time pickers allow users to select a single or a range of dates and times. The picker allows the user to navigate the previous and next set of dates or times.

GDS uses Day / Month / Year date format and 12-hour and 24-hour time systems which are consistent wherever used.

Search

Usage guidelines

Do’s

Always show labels and helper text as placeholders.

Always use the mentioned format for showing dates & time.

Error messages should be short and helpful. Try to use words that the user can understand instead of going full technical.

Use help text ( help icon ) to show hints, formatting, and requirements.
