Component Overview

The Markdown Editor is a text input component that allows users to write and preview rich-formatted content using Markdown syntax. These editors are commonly used for creating documentation, notes, and content-rich UI elements like help texts, tooltips, and descriptions.

Anatomy

Markdown Editor

Toolbar Functionality

The Markdown Editor includes a comprehensive toolbar that empowers users to format content efficiently using a wide range of controls. Basic text styling options include bold, italic, strikethrough, and underline, along with support for headers, quotes, unordered/ordered lists, task lists, subscript, and superscript. Advanced formatting features include inline code, block-level code, and inline/block math rendering. Users can enrich content by uploading images, links, and media clips, inserting tables, flowcharts, and managing prettier formatting for clean syntax. Functional actions such as undo, redo, save, and multiple preview modes (standard, HTML, preview-only) enhance usability. For broader control, users can toggle between full screen, full screen in page, and access catalogs or link directly to GitHub. These toolbar properties make the Markdown Editor a versatile component for structured content creation across documentation and collaborative platforms.

Behaviour

Resizable Section

By default, the Markdown Editor displays two sections side by side — Editor and Preview — each occupying 50% of the screen width. This split layout offers a balanced writing and real-time preview experience.

The divider between the two sections is fully resizable, allowing users to adjust the width of each panel based on their preferred focus — whether they want to concentrate more on writing or reviewing the formatted output.

This flexibility enhances usability and accommodates various workflows, such as content-heavy editing or detailed design reviews.

Fullscreen in page

The Markdown Editor is designed to be fully functional within the browser window, providing a seamless, in-page editing experience.

Fullscreen Mode

The Markdown Editor supports a fullscreen mode, allowing users to expand the editor to occupy the entire browser window. This interaction is designed to minimize distractions and help users focus entirely on writing and formatting content. It's especially useful for long-form documentation, blogs, or any content that requires deep attention.

Preview

The preview panel is enabled by default, allowing users to see real-time formatted output as they write. However, it can be easily toggled on or off using the preview icon in the toolbar, giving users control over their editing space based on their preference.

Preview Only

Preview-Only mode hides the editor panel and displays only the rendered Markdown. This view is ideal when users need to review formatted content without the distraction of the raw Markdown input.

HTML Preview

The content displayed in the preview section is automatically converted from Markdown to HTML. Users can switch to HTML Preview mode to view the underlying HTML output, which is helpful for validating structure or copying the final markup for implementation.

Catalog

All the content added in the editor is automatically organized and represented as a catalog within the editor. This provides users with a structured overview of headings and sections, enabling quick navigation through long or complex Markdown documents.

Usage Guidelines

  • Use proper Markdown syntax: Use #, ##, -, *, etc. to maintain structured, semantic content.
  • Preview before publishing: Always use the right-side preview pane to validate how the final content will render.
  • Use formatting toolbar: Utilize the top formatting bar to apply headings, bold/italic text, lists, links, and tables.
  • Insert links properly: Use [Link Text](https://example.com) format to ensure accessibility and clarity.

❌ Don’ts

  • Don’t write without structure: Avoid long unbroken text or skipping heading levels (# to ### directly).
  • Don’t misuse inline code or pre tags: Use backticks () for inline and triple backticks () for blocks.
  • Don’t paste unsupported HTML: Stick to Markdown wherever possible—HTML may not render correctly in preview.
  • Don’t overload with styles: Keep formatting minimal and consistent; avoid bolding entire paragraphs.
  • Don’t break links or images: Check that all external references work correctly before sharing.
