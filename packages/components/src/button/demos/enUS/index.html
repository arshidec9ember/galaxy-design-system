Anatomy

Variations

GDS has four types of buttons. Each of which has sub-variations based on emphasis, size, and icon positioning.

  • Default Buttons

  • Danger Buttons

  • Static Buttons

  • Floating Action Buttons (FAB)

  • Plain Buttons

Default buttons

These are the standard buttons, that are used for most of the scenarios. They have three styles based on levels of emphasis: Primary, Secondary, and Tertiary

  • The Primary buttons are used for the principal call to action on a page or in a section of a page. They communicate strong emphasis and catches user’s attention to it.

  • The Secondary buttons are used for secondary actions. They have low emphasis and doesn’t catch a lot of attention.

  • The Tertiary buttons are used for actions with lowest prominance. They are visually very subtle and merges well the interface.

All these three types of buttons have further variations: Text only, Text with Icon and Icon only.

Danger Buttons

Used for specific actions that are destructive in nature and can affect users’ data on the platform. For example, delete or remove.

The danger button has three styles based on different levels of emphasis:
Primary, Secondary, and Tertiary

Each style comes with three variants: a) Text only b) Text with icon c) Icon only

Static Buttons

Static buttons are used over colored background or rich graphical elements. For example, GDS uses static buttons on the dark variant of the Global Header, on the Home Page Banners, etc.

The static button also has three styles based on different levels of emphasis:
Primary, Secondary, and tertiary

Each style comes with three variants: a) Text only b) Text with icon c) Icon only

Floating Action Button ( FAB )

As the name suggests this button variant is floating in nature. It is represented with a shadow effect (by using the “shadow-medium” token) and is distinguished from the standard primary button by its rounded sides. It is generally used to show actions that are global in nature, like help & support features.

FAB also comes into two styles based on different levels of emphasis:
Primary and secondary

Each style comes with three variants: a) Text only b) Text with icon c) Icon only

Plain buttons

Plain buttons as we define it is tertiary in nature and uses the primary color of the theme. Mostly used for less important actions like “View details“, “View all”, “See more”, “Previous“, “Next“ etc.

Plain button comes into only one style which is just text along with icon similar to our tertiary buttons.

This style comes with three variants: a) Text only b) Text with icon c) Icon only

Sizes

GDS supports three sizes for the standard Primary, Secondary and Tertiary buttons:

  1. Default ( 36 px )

  2. Small ( 32 px )

  3. XSmall ( 24 px )

The Danger buttons also come in three sizes:

  1. Default ( 36 px )

  2. Small ( 32 px )

  3. XSmall ( 24 px )

The Static buttons come in a single size:

  1. Default (36 px)

The FAB button is available in two sizes:

  1. Default (36 px)

  2. Small (24px).

Plain button is also available in two sizes:

  1. Default: 14 px font size with 20 px line height

  2. Small: 12 px font size with 16 px line height

These buttons have no extra paddings on surrounding, So that it can be used inline with rest of the content.

States

There are six states for each type of button:

Enabled : The typical state of a Button that represents it can be interacted with and is not in a selected state.

Hover : This state defines how our buttons react when hovered over.

Focused : The focused state communicates when a user has highlighted an element using a keyboard or voice.

Pressed : The active state communicates a user click, tap, or press.

Disabled : This state is used when you want to block all interactions on button such as hover, focus and click.

Loading : Loading state communicates a simple processing state of the system based on the user’s action. For example, while saving data on a server.

Behaviours

Tooltip on Icon only buttons

When using the icon-only buttons, a tooltip is displayed on hover with a label. This improves the accessibility of the icon-only buttons.

Loading state

In the loading state, the button icon and the label disappears and an animated loader is displayed. The button is disabled as well for the duration of the loading/processing. The width of the button remains the same.

Flexible Width

The width of a button automatically adjusts to fit the text. While the height of the button is fixed and depends on which size of button we are using ( XS, Small, Default, Large )

Keyboard focus

Users can trigger a button by pressing Enter or Space while the button has focus.

Minimum Width

  • For “Text only” buttons : Use padding of 12 px on each side to define width.

  • For “Icon only” buttons : Use padding of 8 px on each side to define width.

  • For “Text with icon” buttons: Use padding of 8 px on the icon side and 12 px on the text side.

Buttons versus links

Links are used primarily for intra product navigation or to switch to different screen all together. On the other hand, Buttons are used primarily for actions such as “Add”, “Cancel“, “Save“ etc.

Now plain buttons which looks similar to links should be used for less important actions like “View details“, “View all”, “See more”, “Previous“, “Next“ etc.

Usage Guidelines

Button texts should clearly indicate an action. Most buttons should start with a verb.

Avoid using nouns and adjectives.

Use button variations to emphasis different actions as per their importance.

Don’t use multiple primary buttons together

Don’t use punctuation marks such as periods or exclamation points in buttons.

Avoid using the light static buttons on a light background and the standard primary and tertiary buttons on dark backgrounds.

Avoid communicating the system progress with the loading state of a button if it generally takes more than 5 seconds. Consider using a progress bar instead. And wait for 1 or 2 seconds before changing the state to loading, to avoid flickering, if the processing completes in ~ 1 to 2 seconds.
