Anatomy

  • Column Header: Title for the column with the options to sort the column or to perform column-related operations.

  • Cells: Cells are smallest unit of a table that displays data in a specific format.

  • Rows: Horizontal stacking of cells. Row operations are applied on rows (e.g. Selecting a row).

  • Columns: Vertical stacking of cells. Column operations are applied on columns (e.g. Column sort).

  • Sort indicator: It indicates that a column is sortable.

  • Column Action: It contains actions that are contextual to the column.

Supported data types in the table cell

By default, tables support different data types to display a range of content.

Text: Used to display text information.

The text can be either left-aligned (to display general text data or qualitative numeric data) or Right aligned (to display quantitative numerical data).

Icon + Text: Used to display text information with a supported icon. Again it can be Left aligned and Right aligned.

Image + Text: Used to display text information with a supported image. Again it can be Left aligned and Right aligned. The image can be configured to be 1:1 or 16:9.

Badge Group: It is used to display badges. More than one badge can be displayed. All types of badges are supported.

List: It is used to display a list of items. More than one list item can be displayed.

Avatar: It is used to display the Avatar of a user.

Status: Used to display the Status Indicator. All variations of the status indicator are supported.

Link: Used to display links both internal and external links are supported.

Action: Used to display row-level action, all types of actions are supported.

States :

In the table, Only the Column header and Rows have states.

Table Rows:

It supports three states:

  • The table’s row hover state can help your user visually scan the data in a row. The hover state is not interactive.

  • A table row will only transition to a selected state when a selection (Whether single select or multi-select) is performed on the row. This helps users easily identify the selected rows.

Column Header:

By default column headers have all the common states: Default, Hover, Focused, and Pressed. However, if sorting is disabled then the column header has only Default and Hover states (Hover state, in this case, is non-interactive)

Configurations:

GDS Table can be configured with Top bar and Pagination to enable more functionalities.

Pagination:

Pagination divides table data into separate pages. Pagination indicates the current page in view and offers controls to incrementally navigate to the previous or next page. See the pagination component for further guidelines.

Top bar:

Table Name and contextual action can be configured in Top-Bar. See the Top-bar component for further guidelines.

Behavior:

Sorting:

Columns can be sorted in ascending or descending order. Sorting controls are located in the column headers and indicated with an arrow icon when a column has been sorted.

To sort easily the entire column header is clickable.

Multi-Select:

The table supports multi-selection using check box control. The checkbox button is placed in the first column on the left side. This type of behavior is used in picker patterns.

Multi-Select behavior with Top bar:

Multi-Select behavior can be configured with the Top bar to give “bulk action” functionality. Bulk actions are functions that may be performed on multiple items within a table. Once the user selects at least one row from the table, the bulk action top bar appears, presenting the user with actions they can take. To exit or escape “bulk action mode”, the user can click “Clear Selection” or deselect the items.

Single-Select:

The table supports a single selection radio button control. Only one row can be selected at a time when using the radio selection. The radio button is placed in the first column on the left side. This type of behavior is used in picker patterns.

Expandable Row:

The expandable row is useful for presenting large amounts of data in a small space. Use the expanded section for supplementary information. Although this expanded slot can be used to show any type of data display component, please be cautious while using it, and only show row-related contextual information.

Pinning Column:

The column header menu can provide the option to pin columns either to the left or to the right. In a horizontal scroll situation, the user can pin a column containing useful information. Pinning as a feature is both user and system configured.

The designers can also by default pin some columns based on the context of the product.

Copy string:

A copy action can be configured in the cell for users to copy the data of the cell. The copy action copies the entire string irrespective of whether it is truncated or not.

Column Show/Hide

Table Column Show/Hide allows u to choose which columns they want to display or hide in a table. This feature is particularly useful when dealing with large tables that contain a lot of data, as it allows users to focus on the information that is relevant to them.

This feature typically saves a user's selections as a preference, so the next time they access the table, it will display according to their previously saved preferences.

Row Grouping

Table grouping allows you to group data rows in a table based on common values in one or more columns. This functionality is particularly useful when dealing with large amounts of data, as it allows users to easily organize and summarize information. The groups are displayed as collapsed rows that can be expanded to reveal the individual data rows within each group.

Text Truncation and Wrapping:

By default, table cells support both truncation and wrapping. Based on the context and use case these overflow properties can be configured.

Horizontal Scroll:

When the columns occupy more than the available space of the viewport, a horizontal scroll is enabled. This ensures that the table column does not break on different viewport sizes. To reduce horizontal scroll designers can apply Text Truncation and Wrapping on relevant columns.

By default the row operation column, the action column, and the link column are fixed during horizontal scroll to ensure that any interaction with the table is not hidden. The designers can choose to override this behavior.

Vertical Scroll:

When the column occupies more than the available space of the viewport then vertical scroll is enabled. The scrolling behavior depends on the header and the footer of the table, the scroll behavior is designed in such a way that it avoids multiple vertical scrolling.

Usage guidelines:

Don’t use a left-aligned Header with the right-aligned data.

For “view detail action” always try and support the icon with a text label like “View”, to better signify the intent of the action.

Always keep the text in the table header uppercase, this is done to ensure good visual hierarchy.
