Anatomy

Modal component is composed of 3 sections: a Header, the Body and a Footer

The header and footer have limitations, but the body section can accommodate any metadata which is related to the task or information.

Elements

Header

Modal header appears at the top of the container and act as a mega identifier to provide extra context. We use “Header” as an utility component here and supports all the use-cases. For more info on headers check here.

Body

Body is the core of our modal component and by default is an empty container which can host different components inside it like “Form fields, Messages (error, success, warning) and text content as well as the images”.

Footer

The footer has a container area that can hold button groups. Purpose of the footer is to provide a set of actions specific to the type of modals.

Same as Headers, we are also using Footer as an utility component which is being used across different UI shells. For more info on footers, check here.


Templates

Modal is just an empty container which can host different components inside it. So for options we have modal as a base container with header and footer available.

And for ease of use to our dev and design people, we are also providing pre-builted variations of few of the major use-cases like Feedback modals and Banner modals

Modal as base container : Modal with header and footer in builted. And for Body, it’s an empty container which can host different type of information or controls needed to complete the modal’s task.

Feedback Modal : A variation of modal which is used to display important information that users need to acknowledge.

From anatomy point of view, this is just an empty modal container hosting “Empty & Error states” component to support this use-case.


Banner Modal : A variation of modal which is specially designed for a use case from onboarding journey. Use this type of modal to introduce or simply educate users about some new features of your products.

Sizes

We have thee responsive sizes of modals : Small, Medium and Large.

Selection of which size to use depends on what type of information you want to show.

Small : 360 px fixed width

Medium : 560 px fixed width

Large : 720 px fixed width

Behaviours

Modal are a type of dialog used to present critical information or request user input needed to complete a user’s workflow. Modal interrupt a user’s workflow by design. 

When active, a user is blocked from the on-page content and cannot return to their previous workflow until the modal task is completed or the user dismisses the modal. While effective when used correctly, modals should be used sparingly to limit the disruption to the user.

Modal Width & Height

Small modal has a default width of 360 px. The Minimum height is 364px, which is the addition of Header(64px), body( min : 216 px ) and footer (84px).

The Modal will grow in height with the amount of content in it. Once the modal reaches 50% of the height of the viewport, the body will begin to scroll.

Medium modal has a default width of 560 px. The Minimum height is 364px, which is the addition of Header(64px), body( min : 216 px ) and footer (84px).

The Modal will grow in height with the amount of content in it. Once the modal reaches 80% of the height of the viewport, the body will begin to scroll.

Large modal has a default width of 720 px . The Minimum height is 364px, which is the addition of Header(64px), body( min : 216 px ) and footer (84px).

The Modal will grow in height with the amount of content in it. Once the modal reaches 80% of the height of the viewport, the body will begin to scroll. At viewports smaller than 720 px, the Modal will shift to the default width 360px.

Usage Guidelines

Do’s

  • Use Modal is to display important information that users need to acknowledge before moving forward with a task or workflow.

  • Modals have a title and description

  • If more attention is required it can be accompanied by an illustration inline with the title.

  • Give clear context to resolve the issue

  • Follow the consistent modal pattern

  • Action buttons follow respective semantic colors

Don’ts

  • Do not show more than one modal at a time.

  • Do not have any action button focused by default, keyboard users might accidentally press enter

  • Do not use modals for success messages unless its important. Use for success only if the activity is heavy and showing them in modal makes the user feel in control. Can use snackbar/toast instead.
