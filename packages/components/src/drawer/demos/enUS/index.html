Anatomy

Elements

Header

All side sheets have a header. This appears at the top of the container to provide context. It has high visual emphasis and is a mandatory part of the side sheet.

For more information on header, refer to the Header & Footer document.

In case of navigation inside side sheet itself, a back button will come inside left slot of header to support backward navigation. And close icon is configurable depending on the use cases.


Body

Body is the core of the side sheet component. It acts as a container to host several other UI components on it. Like form fields, cards, images, tables, alert banners, etc. It is scrollable when there’s more content than that fits the view. 


However, to avoid placing too much content on the side sheet, it might become hard to access the content due to the limited width of the sidesheet. A bottomsheet can be used instead.

Footer

The footer container holds button groups. The purpose of the footer is to provide a set of actions. For more information on Footer, refer to the Header and Footer document.



Variations

The side sheet usage is based on the components used in it. The variations of the sidesheet are based on the same aspect. 

For example, A side sheet can contain either one column of form fields, two columns of form fields, one or more columns of cards, tables, etc.


Behaviours

When active, a user is blocked from the on-page content until the side sheet is closed. It displays with a shadow, using the shadow token “shadow-High”. While effective when used correctly, the sidesheet should be used sparingly to limit the visual disruption.

Open and Close

Side sheet opens from the right edge of the screen with a slide in animation, and a shaded skim with a transparency is displayed over the rest of the screen. Side sheet is closed using the close icon on its header. On closing, the sheet slides out to the right edge of the screen and the skim disappears.

Side Sheet Height & Width

The minimum width of the side sheet is 360px which is the 1 column form field layout and the maximum width is 1120px. If the content requires more width, consider using a bottom sheet instead. Height of the side sheet always occupies the full screen height.

Bottomsheet vs Sidesheet vs Modals

When to use which UI shells can be tricky so we defined certain use cases where to use what shell

Bottomsheet: In case of wizards, Big forms and multi step flows, Please use bottomsheet to provide maximum available space and easy accessible information

Modal : In case of just feedback confirmations from users (for eg : Delete confirmation) or small forms consisting of 2-3 input fields, Please use modals for all those use cases.

Sidesheet : Sidesheet comes with limited availability of space. So please use side sheet whenever you need to show larger forms, quick selection from long lists/cards/tables.

But refrain from using sidesheet to show multi step forms because currently we don't support stepper inside a sidesheet.

Usage Guidelines

Don’ts

  • Do not show more than one side sheet at a time.

  • Do not use side sheet for success messages or any other feedback related use case. Use a Modal instead.
