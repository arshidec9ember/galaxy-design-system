Anatomy

Variations

Plain & Rich

The plain type has simple key/value pairs where as the rich has bigger icon to denote the key. It also has richer visual than the plain type.

Highlighted

Incase if we want to highlight the section to give the content more emphasis we can use the different BG instead of white. It helps the user to consume the main content on the go.

Nested

Nested view content is a visual representation key/values pairs which has multiple levels, which is like tree structure. There is no restriction in no. of levels and childs in each, but currently in figma component we are supporting upto 4 levels. The logic is for each newer level there is addition of the indentation which is 32px. By default all the levels will be in collapsed state.

With vertical tabs

Incase multiple sections or multiple view content stacking on a page it might be difficult for the use to navigate, instead of long vertical area and to avoid scrolling we ca use view content with the vertical tabs. Here the tabs element is act as the section header.

Elements

Header

Header acts as a initial identifier to provide extra context for the view content. It is an optional element and can be used when required. It also have description which is an optional element. On RHS, it has few actions which can be configurable as per the usecase. For eg. Add or Edit action.

Body Container

Body Container which holds Key/value pairs. The key is just a text content act as a title, The values can be text, link, badge, image/avatar, image preview etc.

Short & Long text: This type is used for Simple text either short or longer one.

Link: To provide links for the values, it will open any page as per the context.

Badge: To showcase the badge, we can also use this placholder to show status indicator, colored badge.

Avatar/Image: To showcase any use profile or any values which has image in it.

Image preview: This has some image data which can be open and viewed by using the image preview component.

Features

Row Divider

Each row item has a divider by default to improve the readability while scanning the content.

Section Sub heading & Section Divider

We can segregate each section by a section divider, and we can also provide section sub heading to identify the content of the section properly.

Row Action

Few row item like text, badge has a action and its also an optional element. The requirement of action on the row item is depends upon the usecase. One example is we can give copy action for ID, which is shown in the image below.

Help Icon

For few items we can add help icon next to the Title, Subheading or Label as per the use case. It can be used to open a tooltip on hover with the help text content in it.

Alignment: Left/Right

By default the plain key value pair is left aligned, but for certain types of text content which has numerical value like currency, weight, volume, etc.

Behaviours

  • The width of the Content View is flexible. It can be shrinked or expanded as needed.

  • the Height of the Container is depends upon the content inside it, if we need to provide more data on minimal space we can also provide show more/less accordion to hide few items and view upon the click.

Inside Sidesheet

View content can be placed inside a sidesheet, with or without the header and border as per the need.

Error states

If the total data failed to appear it can handle through the error state component, and if any single value failed to load we can show the colored badge with some error text.

Usage Guidelines

Use badge component to show the status if any.

Avoid using right aligned row item type for normal text.

Avoid using the subheading if there is no need
