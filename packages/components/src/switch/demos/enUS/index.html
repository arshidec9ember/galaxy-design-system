Anatomy

Variations

A Switch field component is categorized into three types based on usage.

  • With Description: Contains an additional description to the field providing users with more information.

  • Without Description: Primarily used with precise information that needs to be configured.

  • Group Switch: Allows users to perform multiple configurations.

States

Interactions aid users in understanding every state of the component the user interacts with, the switch contains four states namely

  • Default: The default state is a state zero of the component before the user interacts or performs any action over it.

  • Hover: It defines the visual feedback of the switch when hovered over.

  • Focused: Focused is triggered when a switch is activated by either clicking or navigating to it using the keyboard or voice.

  • Disabled: It is an inactive state where the user can not interact with the component. A state change can be triggered by providing permission to edit or by performing a prerequisite action.

  • Error: It represents the error and highlights the field the error state is triggered when the field validation fails.

Behavior

The Switch component is a binary action component that enables users to turn a feature "on" or "off". This component is primarily used to configure the properties of a system, user, or entity, and its typical behavior involves toggling between two states.

Usage guideline

Don’t

As a guideline for usage, it is recommended not to use a Switch Field as a replacement for a Choice Group. While both components allow users to make selections, the Switch Field is designed to handle binary actions, whereas the Choice Group can handle multiple options. Therefore, it is best to use the appropriate component based on the nature of the selection.
