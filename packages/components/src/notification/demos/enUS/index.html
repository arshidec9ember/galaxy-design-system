Anatomy

Variations

Toasts are classified into four types based on semantic usages:

  1. Information is Used to convey neutral information and may not require as much attention from the user.

  2. Success is Used to convey success or completion messages.

  3. Warning is Used to displaying warning and caution messages.

  4. Error Used to alert users of an error or a failure scenario.

The toasts are grouped into two categories Single line toast and Descriptive toast.

Placement

The placement of toasts by default is on the bottom right corner of the interface.

Configurations

Configurations are used to modify the toast component structure depending upon the use case for which they are used. The below mentioned configurations are available for toasts :

Single Line Toast

The single line toast is a single line of feedback message containing a verb phrase associated with the action performed by the user. The character limit of a single-line toast should be within 38 characters to avoid wrapping up multiple lines.

Descriptive Toast

A descriptive toast contains a heading along with a description. It allows the feedback message to be a bit more elaborate. This does not mean that the description should be more verbal. The character limit of the toast heading is 38 characters and that of the description is 80 characters.

Single Toast & Multiple Toasts

If there are more than one toast popping up on the screen after the user performs certain actions, the toast configuration can be set to show either one toast at a time on screen or multiple toasts stacked on top of another.

Single Toast : In case of another toast popping up within the auto dismissal time of first toast, the previous toast is replaced and at a time only one toast will be displayed on the screen.

Multiple Toasts : In case of another toast popping up, the previous toast is moved up and the new toast is displayed below it. The toasts are dismissed according first in first out basis.

Actions

Toasts can have an icon-only close button, a secondary button with a contextual action to take, and a tertiary button for an extra action to take.

Behavior

  • Dismissal

  • Text Overflow

Dismissal

Toasts can be dismissed in two ways :

Auto Dismissal: Toasts are dismissed automatically based on a set duration. But when the cursor is positioned over the toast, then it does not auto-dismiss until the cursor is removed and the time out has occurred. Also if user navigates to a different page toast should auto dismiss from the view.

The default duration for the single-line toast is set to 4 seconds.

Voluntary Dismissal: Voluntary dismissal happens when the user clicks on the dismiss action button “x” in order to close the toast or acknowledge the notification.

Text overflow

When the toast description text is too long for the container width, it wraps to the next line.

Usage Guidelines

Do’s

A toast message should always be preferably kept on the bottom right corner of the interface.

A toast message should be as brief as possible, preferably two to four words.

Don't

Avoid long titles to avoid text wrapping.

A Toast message should not contain any critical or time-sensitive information. Consider using a modal or alert.

Avoid long descriptions in a toast.
