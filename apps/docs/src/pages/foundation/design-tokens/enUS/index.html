Design Tokens

Design tokens are named entities that represent atomic design values. Visual interface design consists of granular design data like colors, spacing, typography, shadows, etc. Design tokens store these values in technology agnostic, human-readable names instead of using them as hard-coded values like hex codes, pixel values, etc. This allows the style values to be used consistently and scalably across tools, teams, code, designs and platforms.

Why are tokens important?

Design tokens are important because they provide a systematic approach to managing and maintaining design properties such as colors, typography, spacing, and more. Below are the key reasons why we should tokenise the design properties:

  1. Consistency: Design tokens help maintain visual consistency across different teams and products. By defining colors, typography, and other design properties as tokens, we can ensure that these values are used consistently throughout our products.

  2. Scalability: Design tokens make it easier to scale our design system as it grows and evolves. When design properties are defined as tokens, we can easily update them globally, making it simpler to make changes across your entire system.

  3. Efficiency: Design tokens streamline the design and development process by providing a single source of truth for design properties. Designers and developers can reference these tokens when creating new components or features, reducing the likelihood of inconsistencies or errors.

  4. Adaptability: Design tokens make it easier to adapt your design system to different contexts or themes. By changing the values of these tokens, we can quickly create new themes or variations of our design system without having to redefine every design property.

  5. Collaboration: Design tokens facilitate collaboration between designers and developers. By using a common set of tokens, both teams can work more efficiently and effectively, ensuring that design intent is preserved throughout the development process.

Token Naming in GDS

GDS uses the below token structure for defining token names. A design token’s name describes how it should be used, and each part communicates one piece of its usage.

  1. Foundation: The type of visual design attribute or foundational style, such as color, elevation, or space.

  2. Property: The UI element the token is being applied to, such as a border, background, shadow, or other property.

  3. Modifier: Additional details about the token’s purpose, such as its color role, appearance, or interaction state. Not every token has all the modifier values. For example, color-text-neutral is default color texts, headings, titles etc. and it has only one modifier i.e. color role neutral.

Design Token Examples

Color Tokens

Color tokens in GDS follow the below hierarchy. The atomic color values are tokenised as Global Color Tokens and derived tokens are created as Alias Color Tokens which have meaningful names and specify the context of use.

There are dedicated color tokens for text, links, icons, backgrounds and borders.

To understand more on colors, refer our Colors foundation.

Typography Tokens

To visually align typography across all GDS products, typography tokens include font values, including font family, font size, font weights, and line heights for all text styles.

To understand more on typography, refer our Typography foundation.

Elevation Tokens

Elevation tokens apply shadow to an element.

To understand more on elevations, refer our Elevation foundation.

Opacity Tokens

Opacity tokens apply transparency to an element. Use opacity-disabled for interactive components that are disabled (such as disabled avatar or card), and opacity-loading to content sitting underneath a loading spinner.

To understand more on opacity, refer our Opacity foundation.

Space Tokens

Space tokens reduce decision making and allow for consistent spacing between elements in a page layout. These tokens are designed to be use for horizontal and vertical spacing, in a variety of contexts.

To understand more on spacing system, refer our Spacing foundation.

One of the other huge benefits of using design tokens is that it makes theming super easy and efficient. The fact that styling is applied using the token names, the primitive values of these tokens can be changed independently without making a change across all their instances.

Using Tokens

For Developers

All the design tokens (Global or Alias) are available by default as part of the GDS library. Alias tokens set the default styling of the components. Please don’t update such tokens. Else the styling value updates made by the GDS team will not be auto-updated across the components.

For Designers

Tokens are available as Figma variables. All the components use tokens for styling a component. Like, setting the color, font, radius, shadow and opacity. The spacing tokens are used to add the spacing manually. Refrain from detaching the variables. Using the GDS tokens ensures that you receive all the styling updates easily across all your designs via library updates. Components with detached styles does not get updated if a style value is updated or a different theme is selected.

Using Tokens across non-GDS Components and Layouts

It is highly recommended to use the GDS Tokens across non-GDS components as well throughout a product. Apart from bringing in visual consistency and streamlining the front-end styling, it would make it super easy to change the theme of a product or make product- level styling updates.

Interoperability with Tokens

Since tokens are a technology and tools agnostic way of styling. They can be used across any front-end technology, platform and design tool. And they could also be exchanged between a design tool and technology platform. This also allows us to have a single source of truth as well as a common way of implementing styling.

Managing tokens in Figma

GDS utilizes Figma’s variables & collections to create tokens for different design properties. 

Variables in Figma store reusable values that can be applied to all kinds of design properties and Collections are Figma’s name for grouping these variables of the same types.

Theming using Figma variables as tokens

One of the huge benefit of using Figma variables and collections is theming. Figma allows to create different versions of our design based on a set of variables. These are called modes. If a variable collection has multiple modes, then we can switch modes on layers and elements to quickly change designs for different contexts. 

Here are a few ways we can use modes to switch contexts: 

  • Different color themes, like light and dark modes

  • Different languages to see how copy flows in designs

  • Devices sizes to see how elements look with different spacing and padding

A variable collection's default mode is the left-most mode column of that collection.
