Colors

The Galaxy Design System (GDS) incorporates a scalable color system that adheres to both Accessibility and legibility standards while remaining visually pleasing. This system can be utilized to generate various themes. The GDS color system must follow the principle of "Perceptual Uniformity", where all colors generated by the system appear natural and cohesive. This principle ensures that the colors are consistent in both perception and appearance.

What is Perceptual Uniformity?

Perceptual uniformity, also known as color appearance uniformity, is a principle in color science that aims to produce a color system where any two colors that appear similar to the human eye also have similar numerical representations. In other words, it is a color system where colors that are visually close together are also numerically close together. This principle ensures that the colors in the system are perceived as natural and consistent, regardless of the device or medium used to display them. Perceptual uniformity is essential for creating a visually pleasing and harmonious color palette that can be used in various design applications.

Color Palette

The GDS color palette includes 14 colors, each with 12 shades and 2 base colors (black and white). Out of these 14 colors, every theme has one brand color and 2 accent colors, 1 neutral, 4 semantic and 7 support colors. The neutral, semantic and support colors remain same for all themes (i.e. Tachyon, Olympus and Optum has same neutral, semantic and support colors).

Checkout the palettes for Tachyon, Olympus and Optum along with variables for light and dark modes.

These colors are assigned different roles in GDS to convey specific meaning and serve distinct purposes.

Palette Creation

The Galaxy Design System (GDS) employs the principle of relative luminance metric to ensure the creation of a perpetually uniform color palette. This principle guides us in understanding how to create and use accessible color combinations, with the baseline AA contrast standard of 4.5:1 for most text and 3:1 for large text or graphical elements.

The GDS color system includes a color level system that assists users in selecting the appropriate accessible color pairing. This system enables designers to identify and select color combinations that meet accessibility standards, ensuring that the content is readable and understandable to all users, including those with visual impairments.

Level System

The GDS color system uses a level system based on the relative luminance scale, which categorizes colors according to their luminance value from high to low. The level system consists of 12 levels, with Level 1 representing the lightest color and Level 12 representing the darkest color.

Each level represents a different shade of the brand color, with Level 1 being the lightest shade and Level 12 being the darkest shade in the palette. This level system facilitates the selection of appropriate color combinations and ensures consistent color usage across different applications.

Tool for palette creation

GDS uses Colorbox.io for creating palettes. The Color Box tool operates on the Hue-Saturation-Brightness (HSB) color model, and users can define a range, type of curve, and direction for each of the HSB properties: Hue, Saturation, and Brightness. Users can also specify a base color from which the tool generates the entire color palette. Additionally, the tool provides information on the contrast ratio between different colors, which is essential for ensuring accessibility compliance.

In GDS, for creating any palette we give the below values to the properties:

Base Color: Typically, the base color used to create a color palette is chosen from either Level 7 or Level 8 in the GDS color system.

Hue: It is the hue value for the base color. In the hue range, we keep the same start and end values.

Saturation: The saturation start value is given 0.01 to start from the lightest shade and the end value is given 1.

Brightness:The brightness start value is given 1 and end value is given 0.3 to achieve the required number of light and dark shades for the palette.

These values are kept same for most of the colors but some colors like yellow, neutral etc are tweaked a bit to achieve the desired shades.

Apart from these HSB properties, we can see the steps (0, 0.25, 0.5, 1, 1.5 and so on) on the palette as well. These steps are given if we need intermediate shades between two steps. In GDS, we keep 9 major steps with 3 minor steps. 2 minor steps are in between 0 and 1 and 1 minor step is in between 1 and 2.

With these values set, we can create any new palette by just changing the hue and base color. For any new theme if we need another hue for a color, we should keep the color name same. In this way we keep consistent color names for the design system which can have different values in different themes.

Example: In a new theme if a different shade is required for pink color, we should create the palette using above properties by changing hue and base color but the name of the palette should be pink.

Color Roles

Primary

It is used to pull the additional focus the main actions in the UI. It is used for all primary actions, selected states or elements that communicate brand.

Accent

It is used for headers and banners to represent the brand accent color in the product. These do not require to be highlighted prominently with primary color and hence accent colors should be used.

Secondary

It is used for less prominent components like secondary CTAs.

Tertiary

It is used for minimal prominent components like tertiary CTAs.

Neutral

Use for default text, background and secondary UI elements, such as secondary buttons or icons.

Information

It is used for any informative content in the UI eg: info icon or for communicating something which is in progress.

Success

It is used to communicate a favourable outcome such as success messages, statuses that are active, credit, approved or verified and that do not require any immediate action from user.

Warning

It is used to communicate that something needs attention. Example to show statuses that are pending, updated/modified or require user intervention.

Danger

It is used to communicate danger or serious error state such as error messages, statuses that represent failed, declined, blocked, debit or removed states.

Support

It should be used for elements that don’t have any semantic meaning associated with them i.e. we could change one support color to another and the experience would remain unchanged.

Inverse

The inverse color role offers the possibility of styling elements in situations where a darker background is necessary. In this role, the traditional roles of light and dark colors are reversed.

Specialized Roles

Specialized roles are used in specific components that require detailed visual distinctions

Nav

This role is reserved for the the navigational elements like Sidebar.

Button

This role is reserved for button component.

If in a theme, any component has a specific color requirement, GDS can support that by adding a new specialized role for that component.

Interaction States

States communicate the status of an interactive element. Use hovered, pressed, selected, focused and disabled tokens to create visual changes related to interaction states.

Color Tokens

Tokens are a method of applying color in a consistent and meaningful way across the products. They provide a layer of abstraction from the hex values themselves, making it easy to use.

All the colors available in the GDS library are named. These are the standard color names followed by a number to distinguish the variation of the same color. These names form the global color tokens, which are used to create meaningful alias tokens. Multiple alias tokens can map to the same global token.

To understand more on this topic, refer the Design Tokens document.

Designing in dark mode

Design tokens currently support two color themes: light and dark. Each color design token maps to a different value for each theme so their appearance differs depending on which theme is being used.

We cannot implement light or dark mode without using color tokens everywhere in our product. Hard coded values will not change when the mode is switched.

Color Accessibility

Color plays a key role in legibility regardless of the medium and application. When colors are insufficiently distinct, whether in brightness or difference in hue, low-vision or color blind users might have difficulty discerning letters and graphical elements.

Never rely on color alone to convey meaning. Some people can't perceive color at all, while others perceive limited color, and some colors have different meanings in different cultures.

Contrast Ratio

Contrast is the difference in brightness between any two elements. Web Content Accessibility Guidelines (WCAG) set specific ratios that achieve the minimum required contrast for legibility.

Generally, small text is any size below 24px and requires a 4.5:1 contrast ratio (AAA success criteria). Large text is anything above 24px and requires a 3:1 contrast ratio (AA success criteria). Graphical elements, such as charts in data visualization, also require a 3:1 contrast ratio.

Exception: Text that is part of a logo or brand name has no minimum contrast requirement.

Guidelines

Use the semantic colors Red, Orange, Green and Blue for visually communicating information with corresponding meanings.

Don’t create custom colors. Use the colors available in the palettes to maintain visual consistency and to leverage the color tokens defined in the GDS library.

While creating new color themes and selecting colors from the palettes, ensure that the color contrast is accessible.
